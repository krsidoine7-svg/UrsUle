# Session du 14 Juin 2026 — Audit de Sécurité

**Résumé de la session :**
Forte concentration sur la préparation du MVP V1 d'UrsUle pour la production. Audit de sécurité complet et correction systématique des vulnérabilités aux standards de l'industrie (OWASP).

**Réalisations Clés :**
1. **Verrouillage Supabase (RLS)** : Les tables secondaires ont toutes été sécurisées en lecture/écriture avec des politiques strictes liées à `auth.uid()`. (Migration 018)
2. **Search Path Injection (PostgreSQL)** : Ajout de la contrainte `SET search_path = public` sur toutes les fonctions sensibles (`SECURITY DEFINER`). (Migration 019)
3. **Storage Security** : Création automatique du bucket `task-attachments` et isolation stricte des fichiers utilisateurs via RLS. (Migration 020)
4. **Correction SSRF** : L'Edge Function `webhook-dispatcher` requiert désormais un header d'authentification valide avant de proxyfier les requêtes vers l'extérieur.
5. **Prévention XSS Stored** : Nettoyage du HTML (avec `dompurify`) injecté par Tiptap avant tout enregistrement en base.
6. **Conformité RGPD** : Intégration de la modale de consentement utilisateur.

**État d'avancement :**
Le code est considéré comme "Production-Ready". Plus de vulnérabilité identifiée.

**Décisions / Bonnes pratiques documentées :**
- Les Edge Functions doivent valider les tokens `Authorization`.
- Tiptap : Toujours nettoyer `getHTML()` avec DOMPurify.
- PostgreSQL : Les `SECURITY DEFINER` exigent un `search_path`.
